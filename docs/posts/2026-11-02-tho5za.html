DoorDash 的“数百单”，把代理购物按回了演示阶段

11 月 2 日

DoorDash 说，外部 AI Agent 为它带来的订单，至今只有数百单。这里的外部 agent 指第三方 agent 接入后替用户完成下单，不是平台自己的推荐系统。
对一家以外卖为主业的平台，这个数字几乎可以忽略。它是“至今”的累计口径，而平台的主业就是走量——两者的差距不是几倍，是量级。能力演示和真实交易之间的距离，被这一个数字摆到了台面上。
另一种解释同样站得住：也许平台还没正式开放 agent 下单入口，或者第三方接入的门槛太高，能力没问题，是分发没到。这个解释和“能力不足”用同一组数据分不开，所以数百单只能当作交易侧的落地证据，当不了对 Agent 能力的判决书。
落到排期上，结论很直接：短期内“代下单”不该被当成产品主路径。要为这条链路投入工程资源，先按演示的预算做，别按交易的预算做。这不是说 agent 结账做不出来，而是说做出来之后，走这条路的人还少到无法验证任何假设。
数还缺一个口径：数百单里有多少是重复测试单，目前不清楚。下一个能把上述判断推翻的变量就在这儿——DoorDash 补上统计口径，或者哪天宣布放开 agent 下单接口，量级会自己给出新答案。
 

LongCat-2.5 把多模态对准 Agent，但只有方向

11 月 2 日

LongCat 上线了 LongCat-2.5，官方博客给的定位是 Native Multimodality for Agentic Tasks：原生多模态，直接对着智能体任务去。Hacker News 上这条拿到 52 分、19 条评论，讨论刚起了个头。
能拿来判断的只有“原生”这个词。按通常含义，它指视觉和文本在训练阶段就进入同一个模型，而不是在产品层外挂一个视觉编码器——agent 读屏幕截图、点界面、跨模态调工具，最吃紧的正是这层转换。但官方博客没展开这个词具体指什么，现有材料撑不到更细的地方。参数量、上下文长度、评测成绩、是否开源、API 定价，这几项同样一项都没有。而它们才决定产品团队会不会真把它接进现有 agent 流水线。
所以这条现在只能拿走一个方向：模型侧在往 agent 任务上押。是不是可复用的基础设施，得等模型卡和价格补齐，或者等有人真的把它接进流水线跑一遍。
